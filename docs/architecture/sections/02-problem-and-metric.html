2 Problem Statement and Evaluation Metric

This chapter states the task as the challenge defines it, fixes the file formats the pipeline must read and write, and derives the evaluation metric from first principles. The metric is a macro-average of the per-entity F0.5 score over every Source 1 entity, with an all-or-nothing rule for entities that have no true match. Precision weighting, equal weight per entity and the singleton rule each shape one or more stages of the pipeline described in Chapters 5 to 11; the closing table maps those consequences to the functions in er_pipeline.py that implement them.

2.1 Formal task definition

Three independent data sources describe overlapping sets of real-world businesses. Each record carries a free-text business name, a free-text address and a country label, but no shared key. Source 1 (S1) is designated the deduplicated reference source: every S1 record stands for a distinct real-world entity. Source 2 (S2) and Source 3 (S3) are the sources to be linked. The task is, for every S1 record, to return the set of S2 and S3 records that describe the same business. That set may be empty (the S1 entity is a singleton), contain one record, or contain many records, possibly from both S2 and S3. Neither S2-to-S3 nor S1-to-S1 links are requested; a self-match to an S1 identifier is a validation error.

Formally, let E be the set of S1 entities and O the union of S2 and S3 records. The ground truth is a function g: E → 2O assigning each S1 entity a (possibly empty) subset of O; a submission is another function h: E → 2O on the same domain, with every element of E appearing exactly once. load_split() reads g from train_ground_truth.tsv into a dictionary from S1 identifier to a Python set, discarding empty tokens so that a blank list becomes the empty set.

One structural assumption follows from S1 being deduplicated: because two S1 records never denote the same business, an S2 or S3 record belongs to the ground-truth set of at most one S1 entity. The decision layer exploits this in decode_table(), which keeps each S2/S3 record only in the pair where it scores highest (see Chapter 9).

The country label is an open set. Training records are labelled US or India; test records additionally carry France, which never occurs in training. The rules forbid hard-coding, filtering or one-hot encoding the pipeline to the two training values and require a row for every test S1 entity, French ones included. block() partitions candidates by country but falls back to the full S2/S3 index for a label without counterpart (Chapter 6).

2.3 The evaluation metric

2.3.1 From Fβ to F0.5

For one S1 entity with predicted set h(e) and true set g(e), precision P is the fraction of predicted identifiers that are correct and recall R is the fraction of true identifiers that were predicted. The general Fβ score is the weighted harmonic mean of the two:

Fβ = (1 + β2) · P · R / (β2 · P + R), equivalently 1 / Fβ = (1 / (1 + β2)) · (1 / P) + (β2 / (1 + β2)) · (1 / R).

The parameter β expresses how many times more important recall is than precision. Setting β = 0.5 gives β2 = 0.25 and 1 + β2 = 1.25, hence the formula printed in the problem statement:

F0.5 = 1.25 · P · R / (0.25 · P + R).

In the harmonic-mean form the reciprocal of precision carries weight 0.8 and the reciprocal of recall weight 0.2. Along the diagonal P = R, ∂F0.5/∂P = 0.8 and ∂F0.5/∂R = 0.2, so a unit gain in precision is worth four times a unit gain in recall at a balanced operating point; the statement's "2×" phrasing refers to β = 1/2.

Substituting P = tp / m and R = tp / n, where tp is the number of correct identifiers, m = |h(e)| the number predicted and n = |g(e)| the number true, the per-entity score collapses to a form that makes the asymmetry concrete:

F0.5(e) = 1.25 · tp / (m + 0.25 · n).

Every wrong identifier adds a full unit to the denominator; every missed true identifier adds only a quarter. This is the single most important fact about the metric for the design of the decision layer.

2.3.2 Macro-averaging over S1 entities

The leaderboard score is the arithmetic mean of F0.5(e) over all S1 entities in the evaluation set. This is a macro average: an entity with twelve true matches and an entity with one contribute equally, and an entity with true matches none of which blocking paired with it contributes exactly zero however good the matcher is elsewhere (a singleton with no candidates, by contrast, scores 1.0 automatically). The pipeline reproduces the definition verbatim: f05() implements the per-entity score with its special cases, and macro_f05() averages it over the full key set tr1.entity_id, never over the subset that received predictions. The stdlib scorer utils/score.py implements the same function for independent checking (Chapter 10).

Micro-level statistics such as total true positives are therefore only diagnostics: ten extra true pairs on one heavily linked entity raise the score far less than ten zero-scoring entities turned into correct singletons.

2.3.3 The singleton rule

When g(e) is empty, precision and recall are undefined, and the challenge fixes the score by rule: an empty prediction earns 1.0 and any non-empty prediction earns 0.0. Two further degenerate cases score 0.0: an empty prediction when the truth is non-empty, and a non-empty prediction with no correct identifier. f05() checks these three cases in that order before evaluating the formula. The rule has no middle ground: on a singleton, one spurious identifier costs the entire point, and on a single-match entity one missing identifier costs the entire point too. Whether to emit the first identifier is therefore a symmetric decision; the precision bias comes from the second and later identifiers, since adding one wrong identifier to a correct single match drops the score from 1.000 to 0.556, whereas missing a second true identifier drops it only to 0.833. The optimal threshold is consequently a property of the data (singleton fraction, true-set sizes, classifier calibration), which is why main() sweeps thr over 0.20 to 0.95 in steps of 0.025 and the relative ratio over {0, 0.6, 0.7, 0.8, 0.9, 1.0} on out-of-fold probabilities instead of assuming 0.5.

2.4 Public and private leaderboards

A submission always covers the full test set. During the challenge the public leaderboard scores an undisclosed subset of the test S1 entities; after the deadline the private leaderboard scores the remaining entities and alone determines the final ranking. Two consequences follow. First, the public score is a noisy estimate of the private one, so decisions are driven by the out-of-fold macro F0.5 computed in main() on the training split, not by leaderboard probing. Second, the country mix of the two subsets is unknown, so the French share of the private set may differ from the public one; the per-country match-rate diagnostic printed at the end of main() exists to detect a French match rate that departs sharply from the US and Indian rates before submission (Chapter 10).

2.5 Constraints

No external lookup
External databases, entity-resolution APIs, government registries, geocoding services and internet-derived augmentation are prohibited on pain of disqualification. The pipeline reads only the seven TSV files located by find_data_dir(); its sole network action is the pip install rapidfuzz fallback on ImportError, which installs a library, not data (Chapter 13).
Model licence and size
The final model must carry an MIT or Apache-2.0 licence and have at most 8 billion parameters. The matcher is a LightGBM ensemble (MIT licence) whose parameters are split thresholds and leaf values: each cross-validation fold trains at most 2,000 rounds of 63-leaf trees (num_leaves=63) with early stopping after 100 rounds without improvement, and the final model is refitted for 1.1 times the mean best iteration of the folds. Even at the cap this is a few hundred thousand values, orders of magnitude below the limit.
Format validity
A submission that fails validation is not scored. The rules require exactly one row per test S1 entity, no duplicate rows, no duplicate identifiers within a list, S2/S3 prefixes only, and identifiers that exist in the test set. utils/validate_submission.py mirrors these checks locally and additionally rejects quote characters, empty or whitespace-padded list tokens, rows with other than two tab-separated columns, and, when --candidate is given, any matched identifier absent from the candidate list. It prints PASS and exits 0 only when no issue is found.
Open-set country
The country column must be treated as an unbounded set of string labels; France appears only at test time.
Reproducibility
The final package must regenerate both output files from the raw data using only the code under code/business_entity_resolution/ with pinned dependencies.
