4 System Architecture Overview

This chapter describes the solution as a software system: its architectural style, the modules of er_pipeline.py and the responsibility of each function, the data contracts between stages, the control flow of main() for the training and test splits, the runtime environment with its dependencies and licences, the logging design, and the configuration surface. Chapters 5 to 11 go deeper into each stage; this chapter fixes the vocabulary and interfaces they rely on.

4.1 Architectural style

The system is a single-process batch pipeline: one Python module, er_pipeline.py, with one entry point, main(), that starts from the raw TSV files and ends with the two submission files. There are no services, no state between runs and no intermediate files. The organising principle is a chain of pure functions over two in-memory containers: pandas DataFrames for record-level and pair-level tables, and SciPy compressed-sparse-row (CSR) matrices for the TF-IDF (term frequency–inverse document frequency) representations used in blocking. Each stage takes frames in and returns a new frame out: prep() copies its input before adding columns, block() and features() build fresh frames, and decode_table() copies only the three columns it needs. No function mutates module-level state; the only globals are the lookup tables (NAME_ABBR, LEGAL, ADDR_ABBR, ADDR_STOP), the compiled regular expressions and the start timestamp T0 that log() reads.

Three considerations tie this style to the evaluation. First, the metric is a macro-average of per-entity F0.5 with an all-or-nothing rule for singletons (see Chapter 2), so the decision parameters must be tuned on out-of-fold predictions computed from exactly the features the test path will see; a single linear flow guarantees this because both splits pass through the identical prep() → block() → features() sequence and the column list feats is derived once and reused. Second, the corpus is expected to fit in the memory of a Kaggle CPU kernel, so a scheduler or checkpointing layer would add failure modes without capability; the one memory-sensitive operation, the dense chunk inside topk_sparse(), is bounded by construction (see Chapter 12). Third, the fair-play rules require a reviewer to verify that no external lookup occurs, and a single file whose only network action is an optional pip install rapidfuzz fallback is the easiest artefact to audit (see Chapter 13).

A convention that runs through every stage is positional row identity. After prep() resets the index, every record is addressed by its integer position; candidate, feature and decode rows carry the pair (i1, i2), where i1 indexes the S1 frame and i2 the concatenated S2+S3 frame, and entity identifiers are re-attached only at the edges: by to_lists() on output and by the labelling and recall-diagnostic lines of main(), which index tr1.entity_id.values and tr2.entity_id.values by position. This keeps the look-ups in features() and the group-by operations unambiguous and lets GroupKFold group by i1 so that all candidates of one S1 entity fall into the same fold (see Chapter 10).

4.2 Module map

Figure 4.1 arranges the functions in the five lanes that correspond to the section headers of the source, with main() as orchestrator underneath. Data flow left to right through the lanes; control flows from main() upward into each lane.

Loading. find_data_dir() searches recursively for train_source1.tsv under /kaggle/input, the working directory, its parent and dataset/, and returns the grandparent of the first hit so that one directory holds train/ and test/. read_tsv() reads with dtype=str, keep_default_na=False and quoting=3, so blank fields stay empty strings, a name such as "NA" is not turned into a missing value, and a stray quotation mark cannot swallow the following rows. load_split() reads the three source files, concatenates S2 and S3 and, when present, parses the ground truth into a dictionary from S1 identifier to set of matched identifiers. profile() logs corpus statistics.

Normalisation. basic(), expand(), norm_name(), core_name(), name_parts(), norm_addr() and _addr_nums() are string-level helpers driven by the four lookup tables and the regular expressions _punct, _space, _digits, _postal, _dotted and _ALIAS; prep() applies them column-wise (see Chapter 5).

Blocking. topk_sparse() returns, for each row of one L2-normalised sparse matrix, the indices and cosine scores of its top-k rows in another, in chunks sized from max_cells; pair_cos() computes the cosine of listed row pairs in slices; block() fits three TfidfVectorizer instances and unions four candidate views (see Chapter 6).

Features. jacc() is the token Jaccard index; features() computes every pairwise and contextual feature over the candidate frame with rapidfuzz scorers (see Chapter 7).

Scoring and decoding. f05() is the per-entity metric including the singleton rule, macro_f05() averages it, and decode_table(), decide() and to_lists() turn probabilities into identifier lists (see Chapter 9). Argument parsing, labelling, LightGBM training under GroupKFold, the (thr, ratio) sweep, the refit and the TSV writer live in main() (see Chapters 8, 10 and 11).

Three invariants follow. Because other concatenates S2 and S3, one i2 index space covers both sources and the src column, from which is_s3 is derived, tells them apart. Because feats is reused verbatim on the test frame, the column order emitted by features() is part of the contract. Because to_lists() initialises an entry for every S1 identifier before filling in pairs, an entity with no surviving pair is emitted as an empty row rather than omitted, which the singleton rule and the validator both require.

4.4 Control flow of main()

Figure 4.2 shows the two paths main() executes in sequence. Both splits are loaded and profiled first, so a missing test file fails before any training time is spent.

On the training path the label y of a candidate pair is 1 when the S2/S3 identifier belongs to the ground-truth set of the S1 identifier and 0 otherwise; pairs that blocking never produces are neither positives nor negatives and appear only in the recall diagnostics. GroupKFold(args.folds) with groups=ftr.i1 yields out-of-fold (OOF) probabilities: a probability for every training pair from a model that never saw that pair's S1 entity. The decision parameters are chosen by exhaustive search on the OOF probabilities, and the final model is refit on all pairs with 1.1 times the mean early-stopped iteration count.

On the test path no label is read. block() refits its vectorisers on the test texts, so the n-gram vocabulary of the unseen country is learned from the test records themselves. Matches and the full candidate frame are converted to identifier lists and written in the same loop, so the matches are a subset of the candidates by construction.

Design note. The frame fte that feeds model.predict() is the one written as candidate_pairs.tsv, so the file documents the exact set the model scored, as the organisers define it.

4.5 Runtime environment and dependencies

The intended host is a Kaggle CPU kernel: a Linux container with a fixed Python 3 image in which the libraries below are normally preinstalled (the rapidfuzz import is the only one guarded by an install fallback), the dataset mounted read-only under /kaggle/input and outputs written under /kaggle/working. The script also runs from a shell with --data-dir. No GPU is used; LightGBM parallelises over all cores through n_jobs=-1, while the rapidfuzz loops in features() run in one Python thread and dominate wall-clock time (see Chapter 12). The licence constraint applies to the final model, which must be MIT or Apache-2.0 licensed and at most eight billion parameters. The model is a LightGBM gradient-boosted tree ensemble, MIT licensed, of at most 63 leaves per tree and at most 2,200 trees (the refit grows int(mean(best_iter) × 1.1) rounds, and each fold's best_iteration is capped at 2,000); the BSD-licensed libraries are tooling, not models, and no pretrained weights are loaded. SciPy is not imported by name but enters through the sparse matrices scikit-learn returns, hence its pin in requirements.txt. The rapidfuzz import falls back to a pip install when the package is absent, the only network action the script can take, and it fetches a library, never data (see Chapter 13).

4.6 Logging design

All progress output goes through log(), which prefixes each message with the wall-clock seconds elapsed since import (T0), one decimal in a seven-character field, and flushes immediately so the Kaggle console shows lines as they happen. The prefix turns the log into a coarse profiler: the difference between consecutive lines is the cost of the stage between them. Multi-line frames use bare print(). The floor, ceiling and OOF lines are read together: the gap between the oracle ceiling and 1.0 is loss only a change in block() can recover, and the gap between the ceiling and the OOF score is loss attributable to the matcher and the decision rule. Because F0.5 is precision-weighted and singletons score all-or-nothing, the floor is expected to be low even when recall is high.

Two values are deliberately not configuration: (best_thr, best_ratio) and the refit round count are learned in every run and never stored, so a reproduction cannot reuse stale parameters. params sets no explicit seed and no deterministic flag: LightGBM falls back to its built-in default seeds for bagging and feature subsampling, which keeps a single-threaded run repeatable, but n_jobs=-1 lets histogram construction be split across threads in an order that can vary between machines and builds, so repeated runs may differ in the last decimals of the OOF score; Chapter 11 gives the params additions that make a run bit-exact.

Risk. Because every constant is a literal in the source, a change to one view's k or to the grid range is invisible from the CLI. Any tuning must be recorded in the run log and in Chapter 15, and the ceiling and floor lines of Table 4.3 re-read after each change: a higher k can only raise the ceiling and lower the floor, and under the precision-weighted metric it is expected to move the selected thr as well, so the sweep must be re-run rather than the previous operating point reused.
